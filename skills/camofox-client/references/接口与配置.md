# 调用与配置

## Python 多身份编排

将**实际安装位置**的 scripts 目录加入模块搜索路径。为不同身份分别创建 Client，不改变共享的“当前用户”。以下使用通用示例路径，请替换为实际路径；仅清理本段代码创建的标签：

```python
import sys
from contextlib import ExitStack

sys.path.insert(0, "/absolute/path/to/camofox-client/scripts")
from config import Config
from client import Client

clients = {
    "a": Client(Config(base_url="http://localhost:9377", user_id="profile-a")),
    "b": Client(Config(base_url="http://localhost:9377", user_id="profile-b")),
}
with ExitStack() as cleanup:
    tabs = {}
    for name, client in clients.items():
        tabs[name] = client.call("create", url="https://example.com")["tabId"]
        cleanup.callback(client.call, "close", tabId=tabs[name])
    for name in ("a", "b", "a"):
        print(name, clients[name].call("snapshot", tabId=tabs[name]))
```

Config 构造及 Client 业务调用不隐式读取环境/文件；环境中有默认 userId 也不会覆盖上述配置。实际 profile/登录态隔离由服务端负责，客户端只保证每次按所选配置构造请求。不要把 A 的 tabId 交给 B 的 Client。

JSON 响应直接返回 Python 数据；二进制返回 transport.Response（body 为 bytes）。需要从环境或指定配置文件读取时显式调用 `load_config`，再把得到的 Config 传给 Client。

组合动作不在 `Client.call` 内，由独立层提供，接收同一个 Client：

```python
from observe import click_and_observe
from doctor import diagnose

client = clients["a"]
tab_id = "<profile-a 当前仍打开的 tabId>"  # 使用实际 ID；上例创建的标签已清理
print(click_and_observe(client, tabId=tab_id, ref="e3", observeTimeout=5.0))
print(diagnose(client))
```

`Client.call` 接受仅限关键字的 `timeout=` 参数，作为单次请求的网络预算；不传时使用 `Config.timeout`。`HttpTransport.send` 同样支持它。默认传输按单调时钟更新连接尝试、发送、响应头和正文读取的剩余预算，持续小块数据不会重置计时。系统同步 DNS 解析无法被 socket timeout 中断，因此不是包含系统解析/调度在内的绝对墙钟时限；解析返回时若预算已耗尽，不再连接。自定义传输应遵守 `timeout`，忽略它就无法保证相同的预算行为。

## 配置约定

`Config` 是字段、默认值和配置校验的唯一事实源。环境变量由字段名转大写并加 `CAMOFOX_` 前缀，例如 base_url → CAMOFOX_BASE_URL。CLI 全局选项同样由 Config 字段生成，密钥仅从配置文件、环境或 Python Config 传入。

优先级：显式 CLI/Python 配置 > 环境变量 > 指定的 `.env` > Config 默认值。`CAMOFOX_USER_ID=` 留空表示不设默认身份，适用于多个 profile 平等使用：每次访问用户资源都必须显式选择 userId，否则在发送请求前报错；公共 health/openapi 与只读 doctor 不需要身份。不猜账号，只读取规范的 CAMOFOX_* 配置项。

`config.build_config` 在构造 Config 的同时返回逐字段来源（cli/env/file/default）与未知配置项提示，供 CLI 与 `doctor` 共用，避免重复解析。`load_config` 是其只取 Config 的薄封装。

`.env` 支持单行 KEY=value、export 前缀、单双引号、空格后的注释和 UTF-8 BOM；不执行变量展开或引号转义。未加引号的值只有“空格 + #”才开始注释，没有前导空格的 `#` 是值的一部分。引号闭合后只允许空白或注释，注释中的引号不影响值。示例与调用：

```text
CAMOFOX_BASE_URL=http://localhost:9377
CAMOFOX_USER_ID= # 不设默认身份，每次显式选择
CAMOFOX_SESSION_KEY="topic-a" # 可与 "topic-b" 区分分组
```

```text
python scripts/main.py --env-file ./browser.env --user-id research-a tabs
```

`doctor` 会提示未识别的 `CAMOFOX_*` 配置项；客户端不会自动猜测变量名或改写配置。

## 组合动作

`click-and-observe` 与 `doctor` 的参数规格同样定义在 `actions.py` 的 `COMPOSITE` 中，与 REST 动作共用一份事实源；CLI 子命令与参数由此生成，业务逻辑分别位于 `observe.py` 与 `doctor.py`，不在 `main.py` 内堆叠。

### click-and-observe

点击一次并在有限窗口内只读观察同 userId 的标签页差集；它**代替** `click`，不要在其前后再单独执行 `click`，否则会重复点击。返回 JSON 含：`click`（是否执行、原始结果或错误、是否不确定）、`sourceTabId`、`sourceUrl`、`baselineCount`、`candidates`、`polls`、`observe.endedBy`（`new_tabs_found|timeout|observe_error|baseline_failed`）与 `observe.error`。

- 参数：`--tab-id` 与 `--ref`/`--selector`（同 `click`），可选 `--expect-url-prefix`、`--observe-timeout`、`--poll-interval`、`--request-timeout`。参数经 `actions.py` 的 `COMPOSITE` 规格校验，CLI 与 Python 直接调用共用同一份，NaN/inf/0 会被拒绝，避免无限轮询。
- 超时预算：基线用 `min(requestTimeout, config.timeout)`；点击沿用 `config.timeout`；**观察窗口在点击结束之后才独立计时**（慢基线或慢点击不会耗尽观察时间）；每次观察请求超时为 `min(requestTimeout, config.timeout, 剩余窗口)`。
- 基线（点击前的 `tabs`）失败或包含非法元素时不点击，`endedBy=baseline_failed`；点击后读取或解析失败则为 `observe_error`，保留已有点击记录。
- 网络请求受剩余预算约束；系统 DNS 解析限制同上。观察窗口耗尽返回 `timeout`，窗口结束后返回的候选不会被接纳。
- 候选是同用户全部标签页的差集，不按分组过滤；`--expect-url-prefix` 只在候选上附加 `matchesExpectPrefix` 标记，不丢弃任何候选、不自动切换或授权。
- 只发送一次点击，绝不重试；点击报错时保留错误并标记 `uncertain`，随后观察失败也不覆盖已执行的点击。
- 观察只调用只读 `tabs`，不会对候选页执行 evaluate/snapshot，不采集账号或密钥信息。

### doctor

只读诊断，返回配置有效值及来源、`envFile`、`hints`（未知配置项提示）、`issues`、`health`、`healthy`、`connectError`、`version` 与 `versionError`。`access_key`/`api_key` 只报告 `set` 布尔与来源；若服务端 health 或错误详情回显了已知密钥值，整个诊断结果会递归替换为 `[REDACTED]`。只访问公开只读端点（`/health`、`/openapi.json`），不包含 `/pressure/cleanup` 等有副作用的接口，不读取宿主配置或凭据。原子动作的响应输出不受影响。

## 输出呈现

图片、`application/octet-stream` 和 `application/zip` 作为二进制响应处理，CLI 必须用 `--output` 保存；JSON 响应也可保存。输出路径先做非破坏性检查，随后通过同目录临时文件原子替换目标，写入失败保留原文件。

如果业务已返回结果，但格式化或保存失败，CLI 退出码为 1，stdout 返回 `error`、`phase: "output"`、`action` 和原始 JSON `result`。保存这份结果即可取得新建 tabId 或点击执行记录，不要重发动作。二进制的 `result` 仅含 `type`、`status`、`contentType`、`byteLength`、`saved: false`、`bodyIncluded: false`，不包含未保存的字节。

`snapshot` 的 CLI `--output-format` 与服务端 `--format` 是两个概念：前者决定本地如何呈现（`text` 输出 URL、可读快照与中文分页提示；`json` 为默认，保持服务端原文），后者是传给服务端的参数。`text` 遇到缺少 `snapshot` 字符串字段的响应会报明确错误，不静默截断或自动抓取全站。

## 自定义 REST

未预设的动作使用 `request`，先核对目标服务的 `/openapi.json`。示例参数文件：

```json
{"method":"POST","path":"/tabs/真实ID/wait","body":{"selector":"article"}}
```

```text
python scripts/main.py --user-id research-a request --args-file request.json
```

path 仅接受同一服务的相对 API 路径；query 放在 params，JSON 请求体放在 body。身份只在 Config 中设置，不在参数里重复传 userId/sessionKey。POST /tabs 自动注入当前标签组。CLI 不自动跟随 API 重定向，base-url 应指向最终 REST 地址。

普通接口使用 CAMOFOX_ACCESS_KEY。cookie 导入 `POST /sessions/{编码后的用户}/cookies` 优先使用 CAMOFOX_API_KEY，否则使用全局密钥。Trace 列表 `GET /sessions/{用户}/traces`、下载 `GET /sessions/{用户}/traces/{文件名}` 和删除 `DELETE /sessions/{用户}/traces/{文件名}` 优先使用 ACCESS_KEY 以满足全局门禁，未配置时使用 API_KEY。是否授权由服务端决定。

下载 trace 时指定 `--output trace.zip`，客户端保留 ZIP 字节。cookie 导入的 body 中，`cookies` 字段使用 Playwright cookie 对象数组，例如 `{"cookies": []}` 的结构（实际填写待导入项）；没有自动读取本地浏览器或 Netscape cookie 文件的功能。

## 动作参数

服务端契约已在 `actions.py` 补入：`snapshot` 的 `format`(text/json)、`links` 的 `offset`/`limit`、`images` 的 `includeData`/`maxBytes`/`limit`。参数类型与限制以目标服务为准（例如 `images` 的 `limit` 由服务端收敛到 1–20，默认 8）。完整清单仍以运行时 `--help` 为准，不在文档维护第二份副本。

## 调用入口

Python 调用从 `config.Config`、`client.Client` 开始；组合动作用 `observe.click_and_observe` 和 `doctor.diagnose`。Client 的 transport 可注入，业务调用不读写本地文件。

REST 契约参考 [上游实现](https://github.com/jo-inc/camofox-browser/blob/master/server.js) 与 [认证实现](https://github.com/jo-inc/camofox-browser/blob/master/lib/auth.js)，具体能力以目标部署的 `/openapi.json` 为准。
